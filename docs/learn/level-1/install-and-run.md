# 快速装通：把它装好、跑起来

> 这一页是**手把手**。你不用懂原理，照着做就行。每一步我都写了"做成什么样算对""卡住了怎么办"。

## 先看清：装 DSH 有两条路

| | 路 A · 一条命令（官方最简） | 路 B · 源码 + Docker |
|---|---|---|
| 命令 | `npx @deepseek-ai/dsh web` | `git clone` + `docker compose up -d` |
| 前置 | 只需 **Node.js** | 需要 **Docker** |
| 启动 | **一条命令**跑起来 | clone → 进目录 → 起服务 |
| 好处 | **最快**，官方推荐 | 能看源码、可标版本、自己带模型、更可控 |
| 适合 | 想**赶紧跑起来试点** | 想**深入、自己部署环境** |

> 两者都是启动 DSH。**A 最省心，B 更完整可控。** 教程把 A 放最前面，B 作为"想要更多控制"的备路。

> ⚠️ 说明：DSH 迭代很快，**具体字段、命令以[版本列表](/version-status)和我们标"以官方为准"的地方为准**。先跑通，别的以后再说。

---

## 路 A：一条命令跑起来（推荐新手）

> 你只需要**装好 Node.js**，然后一条命令就能把 DSH 跑起来。

### 第 1 步：确认装了 Node.js（没有就先装）

打开终端，跑这条，看有没有版本号：

```
node -v
```

- ✅ 显示 `v22.x` 之类 → 装好了，去第 2 步。
- ❌ 提示 `not found` → 去 nodejs.org 装一个 **Node.js LTS**，装完重开终端再试。

### 第 2 步：一条命令启动

```
npx @deepseek-ai/dsh web
```

✅ **做对了的样子**：它开始下载并启动，最后提示你一个**本地地址**，并（通常）自动打开网页。若没自动打开，你手动在浏览器访问：

**http://127.0.0.1:3080/**

（这就是本机 DSH 的网页界面地址，以你运行的版本输出为准；一般是 `127.0.0.1:3080`。）

❌ **卡住了**：提示 `npx not found` → Node 没装好；提示**权限/网络** → 重试，或换网络。

### 第 3 步：打开网页，跑起来了

浏览器里看到能用的界面，就说明**装通了**。到这里你就能开始"派第一件活"了。

> 💡 以后每次要启动 DSH，就重复"路 A 第 2 步"这条命令即可。

---

## 路 B：源码 + Docker（想要更多控制）

> 如果你想要**完整的源码**、想**自己标版本**、想**自己带模型**，用这条更可控的路。

### 第 1 步：把 DSH 下载到本机

进入你想放代码的文件夹，跑：

```
git clone https://github.com/deepseek-ai/deepseek-harness
```

✅ **做对了的样子**：出现下载进度，最后多出一个 `deepseek-harness` 文件夹。
❌ **卡住了**：提示 `git not found` → 先装 git。

### 第 2 步：进入这个文件夹

```
cd deepseek-harness
```

### 第 3 步：用 Docker 一键起

```
docker compose up -d
```

✅ **做对了的样子**：拉镜像、建容器，最后显示一串服务名并回到命令行。
❌ **卡住了**：`docker not found` → 装/启动 Docker Desktop 再试。

### 第 4 步：确认它真的起来了

```
docker compose ps
```

✅ **做对了的样子**：列出服务，状态是 `running`（正在跑）。**看到 running，就说明装通了。**

## 两条路怎么选（一张表搞定）

| 你想要 | 选哪条 |
|---|---|
| 最快跑起来、先试点 | **A（npx 一条命令）** |
| 只想用，不想折腾环境 | **A** |
| 想看到源码、能改 | **B（源码+Docker）** |
| 想自己带本地模型、要版本管理 | **B** |

> 建议：**先用 A 跑起来**，觉得不够、想深入了再切 B。别一上来就在环境上花太多时间。

---

## 记住这一个词：以官方为准

装通只是第一步。DSH 的配置项、命令名会随版本变化，**以后遇到"怎么配"的问题，答案在[版本页](/version-status)和官方仓库里，别背旧命令。**

## 救急（卡住了看这里）

| 你看到 | 大概率是 | 一句话解法 |
|---|---|---|
| `node not found` | Node 没装好 | 装 Node.js LTS，重开终端 |
| `npx not found` | Node 环境缺 | 装 Node.js，或 `npm i -g npx` |
| `git not found` | 没装 git（路 B） | 装个 git |
| `docker not found` | Docker 没装/没启动 | 打开 Docker Desktop 等 ready |
| 网络/权限报错 | 网络不畅 | 重试，或换网络 |
| 起了却是 `exited` | 有服务没起来（路 B） | `docker compose logs` 看哪个崩，对照[版本页] |

## 走完全程，你做了什么？

- ✅ 用了**最简一条命令**（或源码+Docker）把 DSH 跑起来了。
- 这就是"安装 + 跑通"——你离"会用"只差**真的派一件活**了。
