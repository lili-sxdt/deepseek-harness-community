# 流程编排：串一条 workflow / pipeline

> 你已经会写一个 skill（"怎么干"），现在学**"怎么安排"**——把几个步骤连起来跑，或一次扇出很多再收回。

## 📖 理解轨：pipeline 和 workflow 的区别

这是最容易混的，一句话先分清：

- **`pipeline`（流水线）**：几个步骤**有固定先后顺序**，前一步的输出喂给下一步。像工厂流水线。
- **`workflow`（调度）**：一次把很多**独立**的任务**扇出去**，再**收回**汇总。像项目经理派很多外包。

> 区别的关键：**pipeline 是"一条线接力"；workflow 是"一把扇子散出去再聚起来"。**

## 🛠 动手轨：最简能跑的例子

### 例子 A：一条 pipeline（固定顺序）

假设你想做"数据小流水线"，四步：

```
读入数据 → 清洁 → 算指标 → 出图
```

**你只要**：把每一步做成一个小动作，然后**按顺序把上一步的输出传给下一步**。本质就是"**把上一步的结果，交给下一步**"。

```
第1步 读入   →  第2步 清洁   →  第3步 算指标   →  第4步 出图
     (输出)────►(接第1步)────►(接第2步)────►(接第3步)
```

✅ **做对了的样子**：从头到尾一条线跑完，图出来了。
❌ **卡住了**：某一步的输出没喂给下一步 → 检查"上一步的结果是不是交到了下一步"。

### 例子 B：一条 workflow（扇出再收回）

假设你想"从 10 个角度同时分析一批数据"：

```
① 定义：要做的 10 个角度
② 扇出：为每个角度各派一个 agent 去做（并行、互不干扰）
③ 收回：把 10 个结果收集到一起
④ 汇总：去重、整理成一份清单
```

✅ **做对了的样子**：一次派出 10 个任务、各自干完、最后汇成一份。
❌ **卡住了**：某个任务没收回 → 确认每个任务都返回了结果、并交到你指定的地方。

## 一个新手最容易卡的地方

> 别把心思花在"发明 agent"上——**真正干活的 agent 你已经会用了**。你要动脑的是"**怎么把活分派清楚、怎么把结果收回来**"。规划比代码更重要。
