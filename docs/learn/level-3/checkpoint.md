# 出师检验：做完这几题，你会"用 DSH 做东西"了

> 这一关**不看我上面的页**，独立完成才算过。

## 检验一：能不能说清？（理解）

用你自己的话，讲清 `pipeline` 和 `workflow` 的区别。抓住"**一条线接力 vs 一把扇子散出去再收回来**"就算过。

## 检验二：能不能写一个 skill？（动手）

**自己写一个**最简单的 skill（什么主题随你，比如"给图表统一配色"），放到正确位置，并**触发它用一次**，看它有没有按你的要求来。

- 它生效了 → 通过
- 没生效 → 检查位置/名字对不对，再试

## 检验三：能不能串一条流程？（动手）

选一个你工作里**真实的**小流程，拆成 2~3 步，串成一条 pipeline，让它跑通。

- 跑通 → 通过
- 哪一步断了 → 回到那一步修，再试

## 出师标准一览

| 检验 | 达标 = 你已能 |
|---|---|
| 检验一 | 讲清 pipeline / workflow 的区别 |
| 检验二 | 写一个自己的 skill 并真用上 |
| 检验三 | 把一个真实流程串成能跑的 pipeline |

三题都做到，**第三课「应用构建」你就过了**。✅

你已经"会用 DSH 做东西"了（在它的框架里搭）。下一步是更进一层——**把 DSH 改造成更合你自己用的**：写 plugin、读核心结构、加一个新能力。那是"使用人员"往"开发自己工作的人"走的一步。
