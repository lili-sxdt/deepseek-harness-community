# 编写技能：写一个自己的 skill

> 这是"应用构建"里**最有价值、也最容易上手**的一件事。做完它，你就真的会"改" DSH 了。

## 📖 理解轨：skill 到底是什么

`skill` 就是**一份说明文件**（通常是 `SKILL.md`），告诉 DSH："**当要做某件事时，就按这个标准做。**"

- **打个比方**：它是你给某个岗位写的"作业说明书"——平时收着，做到这一步才翻开照着做。
- **和别的区别**：`agent` 是"干活的人"，`skill` 是"教它怎么干的那张纸"。

> 关键心法：**写 skill 不是发明新东西**，而是"照着已有的样子，填你自己的内容"。DSH 里已经有很多 skill，你只是加一本新的。

## 🛠 动手轨：最简能跑的一个

> 我们来写一个**超级简单**的 skill，让你立刻有感觉。就以"给报告套一个统一封面"为例。

### 第 1 步：建一个文件夹 + 一份文件

在你的工作区里，新建这样一个结构（名字随你，但用英文小写）：

```
.dsh/skills/report-style/
└── SKILL.md
```

### 第 2 步：写这份 SKILL.md（跟着填）

```
# report-style（报告风格）

> 用途：写报告时，套用统一的封面和格式。
> 触发：开始写一份新报告前。

## 一、封面规范
- 标题：居中，用一号黑体
- 副标题：下面一行，用四号宋体
- 致谢/落款：右下角，用五号宋体

## 二、正文规范
- 正文用五号宋体，行距 1.5 倍
- 每章标题用四号黑体

## 三、常见坑
- 标题、正文千万别混用字体
- 落款日期要用"年/月/日"格式
```

你看——**我没有发明任何新东西**，只是**照着一个 skill 该有的样子**，填进了我自己的内容（封面、正文、坑）。这就是"在格子里面填空"。

### 第 3 步：触发它，看有没有用

当你要写报告时，告诉 DSH"按 `report-style` 这个 skill 来"（或它识别到写报告场景会自动用）。然后看它**是不是真的按你写的封面/字体来了**。

✅ **做对了的样子**：它生成的报告，用了你写的标题格式、字体、落款。

❌ **卡住了**：没生效 → 检查你是不是**放对了位置**（`.dsh/skills/<名字>/SKILL.md`），名字是不是对了。

### 再写一个更"实用"的例子：一个数据分析的 skill

上面那个只是"改格式"，再给你一个更接近工作流的——一个"**做数据分析**"的 skill。你看它怎么把"该怎么做一件事"写成标准：

```
# data-summary（数据摘要）

> 用途：拿到一批数据时，先摸清它的基本情况。
> 触发：读入一个新数据集后。

## 一、先做
- 读入数据，打印"行数/列数/每列类型"
- 检查有没有缺失值，各列缺失多少

## 二、再算
- 每列的均值、标准差、最小/最大值
- 如果是分组数据，按组算一次

## 三、输出
- 一段 200 字内的文字说明（别贴一大堆表）
- 存成 <数据名>_summary.txt

## 四、常见坑
- 表头乱码 → 先修编码
- 把"平均值"写成"中位数" → 说清你要哪个
```

> 你看，**一个 skill 就是把"这件事怎么一步步做、最后交什么"写清楚。** 你以后写自己的 skill，就按这个骨架填你的内容。

### 试着改一个现成的 skill（比从零写更快）

DSH 里已经有一堆 skill。**改一个比你写一个新的更快、也更不容易错**：
1. 找到 DSH 里某个现成 skill（比如某个你做过的活对应的）。
2. 打开它，看它的"用途/触发/步骤/输出/坑"。
3. **改**里面的某几步，换成你的标准，保存。

> 这就是"在格子里填空"的另一种姿势：**先填别人留好的格子，改到自己顺手。**

## 你现在做了什么？

你**亲手写了一个 skill，并让 DSH 用上了**。这已经是从"用 DSH"跨到"**为你的工作定制 DSH**"了。

## 两个提醒

1. **从最简开始**：别一上来写很复杂的 skill，先写一个"一套格式"这种最简单的，跑通再说。
2. **先读后写**：动手前，先找一个 DSH 里现成的 skill 看看它长什么样，照着它的骨架来，最省事。
