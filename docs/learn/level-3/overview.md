# 构建总览：在框架里"搭东西"的整体观

> 动手之前，先看清"这一课你要动的，是哪些零件，它们怎么分工"。

## 你手上的"零件"

在 DSH 里，你能用来"搭东西"的主要是这三样：

| 零件 | 是什么 | 打比方 | 你用它干嘛 |
|---|---|---|---|
| `skill` | 一份"怎么做某件事"的说明 | 作业手册 | 告诉助手"按这个标准做" |
| `workflow` | 一段"一次派很多再收回"的调度 | 项目经理 | 一次把很多独立任务扇出去再汇总 |
| `pipeline` | 一段"有固定顺序"的工序 | 工厂流水线 | 前一步喂给下一步，按顺序跑 |
| `agent` | 真正干活的员工 | 员工 | 上面都是"怎么干"，真正干活的是 agent |

## 一个关键区分（别搞混）

- **`skill` 是"怎么干"**——它给助手一条标准/一套做法。
- **`workflow` / `pipeline` 是"怎么安排"**——它把几个步骤安排成一道工序。
- **`agent` 是"真正干活的人"**——上面的都只是规划，最后动手的是 agent。

> 一句话：**skill 教它怎么干，workflow/pipeline 安排怎么走，agent 真正干。**

## 你动手的三步走（本课主线）

1. **写一个 `skill`**：给你的活，立一条"怎么做"的规矩。
2. **串一条 `workflow` / `pipeline`**：把几个步骤，连成一条能跑的工序。
3. **编排 `agent`**：让几个助手分工，拼一个大任务。

## 动手原则（贯穿本课）

1. **从最简能跑的开始**——先让最小的一步跑通，再往上加。
2. **每步可验证**——做完能看出"对不对"。
3. **卡住有救**——每一篇都给你"错的样子"和"救急"。

## 这一课你会学到什么

**你会从"用现成的东西"，变成"自己搭一个能跑的小系统"。** 这已经比"会用"高一级了——你在**为你的工作定制**。
