# 选型决策：遇到一件事，该用哪个？

> 这是第二课**最值钱**的一页。以后你卡住"不知道该用哪个"，就来查这张表。

## 决策表（先查它）

| 你现在的情况 | 用哪个 |
|---|---|
| 就是随口一问 | 直接用主对话（聊天） |
| 想知道"按什么标准做" | 打开对应 **skill** |
| 想让助手**长期**都守某规矩 | 写进 **AGENTS.md** |
| 需要**独立客观**地检查 | 派全新上下文的 **subagent** |
| 想**并行**干几件互不干扰的活 | 派多个 **subagent** |
| 接着**同一个任务**继续往下做 | 用 **subagent_fork** |
| 一次要**扇出很多任务再汇总** | 用 **workflow** |
| 一个**固定顺序**的流程 | 用 **pipeline** |
| 改**某个功能、加个新能力**想即时生效 | 用 **plugin** |
| 只是想把**一件事说清楚** | 调好你的 **prompt** |

## 几条最容易记错的判断

**① "检查成果"该用哪个？—— 用全新的 `subagent`。**
因为它要**独立客观**。如果你让正在干这活的助手自己检查自己，它会带上自己做时的判断（有"偏见"），等于**自审、不算数**。**这是硬红线：检查用 `subagent`，禁止用 `subagent_fork`。**

**② "接着上次继续聊"该用哪个？—— 用 `subagent_fork`。**
因为它**继承旧上下文**，能接着之前的话往下推。

**③ "想加个新能力"该用哪个？—— `plugin`。**
skill 是"教员工怎么做某事"，plugin 是"加一种新能力"。**别搞混。**

## 小口诀（背这个就行）

```
想守规矩 → AGENTS.md
想会做事 → skill
想客观独立 → subagent
想接着旧话 → subagent_fork
想一次派多 → workflow
想连成工序 → pipeline
想加能力 → plugin
想把话说清 → prompt
```

## 自测一下

**现在你刚做完一次数据分析，要检查结果有没有统计错误、有没有夸大。该用哪个？**

- A. 让正在干活的主助手自己再查一遍
- B. 用全新上下文的 **subagent** 独立审
- C. 写进 **AGENTS.md**

**答案：B。** 因为"检查"最要紧的是**独立客观**。让做的人自己审自己=自审、不算数，必须用全新上下文的 subagent。

> 能选出 B，你就把"独立客观 → 全新 subagent"这条最关键的判断抓住了。✅
