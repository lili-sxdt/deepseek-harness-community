# 扩展总览："改框架本体"是怎么一回事

> 动手之前，先看清这一课你到底在动什么、怎么动，以及"能力"和"操作手册"到底差在哪。

## 你这次要动的东西：plugin

`plugin`（插件）——中文读作「插件」，就是**一块可以插进去、让工具多一个新能力**的零件。

- **打个比方**：DSH 像一把多功能瑞士军刀，你**加装一个新功能头**，它就多出一样用途。
- **关键**：`plugin` 加的是**能力**；而 `skill` 只是"**教它怎么做某件事**"。

> 一句话分清：**skill 是"教它怎么干"，plugin 是"让它多出一样本事"。**

## 这一课的定位（很重要）

你不是开发者、不造软件、不贡献开源。你是**一个使用人员**，目标只有一件事：

> **把 DSH 打扮成更配你自己工作的样子。** 比如你的工作有某个很特别的流程，通用的插件没有，你自己加一个，就解决了。

## "改 DSH"其实没那么可怕

很多人一听"改框架"就慌。其实这种"加一个插件"**不需要你重写整个 DSH**，你只是**在它留好的接口里，塞进你自己的一小块功能**。就像给房子加个房间，不是重建整栋楼。

- **你动**：一小块新的功能。
- **你不动**：DSH 的其它一切。

## 动手原则

1. **从最小能跑开始**：先做一个最简单的 plugin（比如"给输出加一个特定格式"），跑通再加大。
2. **先读后写**：动手前，先找一个 DSH 现成的 plugin 看长什么样，照着骨架填。
3. **卡住有救**：每一篇都给你"错的样子"和"救急"。

## 这一课你会学到什么

你会**自己给 DSH 加一个新能力**，并且是为了**你自己的活**。到这一步，你就是"**开发自己工作的使用人员**"了——这正是整站"从入门到精通"的顶点。
