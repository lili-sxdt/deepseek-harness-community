# 架构解读：看懂 DSH 核心结构，知道该往哪儿加

> 前面你"加了一小块"。现在看懂它**整体怎么搭**，你就能清楚地"该往哪儿加、加在哪儿不会坏"。

## 📖 理解轨：DSH 这种"一切皆插件"的架构

DSH 的设计核心是"**一切皆插件**"——模型、工具、提示词、子代理，都能**拆成可插拔的零件**。

- **打个比方**：它像一套乐高——主体是固定的，你可以把不同的积木（模型、工具、智能体）插到对应接口上，随时换、随时加。
- **对你意味着**：你想加的东西，只要找到"它在哪个接口上"，插进去就行。

## 它其实是一堆"接缝"，你往接缝里插

DSH 是靠 **`ctx.*` 接缝**暴露能力的（下面是**概览**，完整版见[深度参考·真实接口](/deep-dive/api)）：

| 接缝 | 是什么 | 你想加就…… |
|---|---|---|
| `ctx.tools` | 工具 | 注册新工具 |
| `ctx.skills` | 技能 | 加作业手册 |
| `ctx.subagents` | 子代理 | 委托外包 |
| `ctx.workflowEngine` | 工作流 | 一次扇出很多再收回 |
| `ctx.llm` | 模型 | 换/接模型 |
| `ctx.jobs` | 后台任务 | 挂长任务 |
| `ctx.session` | 会话 | 记过程 |

> 一句话：**你加"新能力"，就往对应 `ctx.*` 接缝里插；其它几块（换模型/加工具/改标准）也是各自的接缝。**

## 🛠 动手轨：看一次真的

**尝试**：在 DSH 的源码/配置里，找到它的插件目录（通常在 `plugins/` 或你后来放插件的地方），打开一两个看。你会发现**每个插件都接在约定位置、有固定格式**，而不是乱塞。

✅ **做对了的样子**：你能看出"插件都插在约定接口上"。
❌ **卡住了**：不知道在哪儿 → 找它的配置/目录结构说明，或搜"plugins"。
