# 架构解读：看懂 DSH 核心结构，知道该往哪儿加

> 前面你"加了一小块"。现在看懂它**整体怎么搭**，你就能清楚地"该往哪儿加、加在哪儿不会坏"。

## 📖 理解轨：DSH 这种"一切皆插件"的架构

DSH 的设计核心是"**一切皆插件**"——模型、工具、提示词、子代理，都能**拆成可插拔的零件**。

- **打个比方**：它像一套乐高——主体是固定的，你可以把不同的积木（模型、工具、智能体）插到对应接口上，随时换、随时加。
- **对你意味着**：你想加的东西，只要找到"它在哪个接口上"，插进去就行。

## 一个简化的"往哪儿看"框架

你不用记代码，只要知道——DSH 大概由这几块组成：

| 部位 | 是干嘛的 | 你要动它会动到哪 |
|---|---|---|
| 模型 | 真正"思考"的部分 | 想换/接模型 → 走这里 |
| 工具 | 它能"动手"做的事（读文件、跑程序等） | 想要新工具 → 走这里 |
| 提示词 / 技能 | 教它"怎么干" | 想改标准 → 走这里 |
| 子代理 | 派出去独立干活的"外包" | 想编排分工 → 走这里 |
| 插件 | 加新能力的"插口" | **你想加新能力 → 走这里（本课）** |

> 一句话：**你要加"新能力"，就动 plugin；其它几块的改动，换模型、加工具、改标准，是另外的事。** 本课你专注 plugin 这块。

## 🛠 动手轨：读一个它长什么样

**尝试**：在 DSH 的源码/配置里，找到它的插件目录（通常在 `plugins/` 或你后来放插件的地方），打开一两个看：

1. 每个插件开头是不是都写了"**它做什么 / 怎么接入 / 输出什么**"？
2. 它是不是**插在某个接口上**，而不是乱塞？

✅ **做对了的样子**：你能看出"每个插件都接在约定位置、有固定格式"。
❌ **卡住了**：不知道在哪儿 → 找它的配置/目录结构说明，或搜"plugins"。
